# PSOC&trade; Control C3M/P8: Secure-Non-Secure template

This code example applies for PSOC&trade; Control C3M/P8 MCUs. This code example illustrates communication between the Secure Processing Environment (SPE) and the Non-Secure Processing Environment (NSPE) on the TrustZone-enabled Main CM33 core of the PSOC&trade; Control C3M8 device. At runtime, it demonstrates basic UART I/O by printing the “PPCA Core 0/1 Variable” message to a terminal and toggling LEDs. The UART peripheral is controlled by the SPE, while the NSPE invokes a Non-Secure Callable (NSC) function to forward the log message to the SPE, which then outputs it via the UART.

This code example has a four-project structure: a CM33 Secure project, a CM33 Non-Secure project, and two CM33 projects associated with the PowerPC Architecture (PPCA 0 and PPCA 1)

## Design and implementation

This template application has a four-project structure, with separate projects for the Secure Processing Environment (SPE) and Non-secure Processing Environment (NSPE) of the Main CM33 core.

**Table 2. Application projects**

Project | Description
--------|------------------------
main_cm33_s | Project for CM33 Secure Processing Environment (SPE)
main_cm33_ns | Project for CM33 Non-secure Processing Environment (NSPE)
ppca_cm33_0 | Project for PPCA0
ppca_cm33_1 | Project for PPCA1

The secure project (`main_cm33_s`) runs first: it configures the memory protection controller (MPC) to partition flash and SRAM, and the peripheral protection controller (PPC) to expose peripherals to the non-secure world. The debug UART (SCB2) is intentionally kept secure so it remains under SPE control. The SPE initializes the UART via the `retarget-io` middleware, prints the startup banner, and then launches the non-secure application.

To allow the NSPE to produce log output without owning the UART, the SPE exposes the `log_msg()` non-secure callable (NSC) function (declared with `cmse_nonsecure_entry` in `main_cm33_s/nsc.c`, prototyped in `shared/nsc.h`). The non-secure application writes formatted text into a `CY_SECTION_SHAREDMEM` buffer and calls `log_msg()` via the `LOG()` macro, which transitions execution into the secure world through the NSC veneer and prints the message prefixed with `[NSPE]`. The non-secure project (`main_cm33_ns`) logs a startup message, and blinks the user LED in a continuous loop.


### Resources and settings


The application uses the UART to print messages on the UART terminal. The UART resource initialization and retargeting of standard I/O to the UART port is performed using the [retarget-io](https://github.com/Infineon/retarget-io) library.

**Table 3. Application resources**

Resource  |  Alias/object     |    Purpose
:-------- | :-------------    | :------------
 UART (HAL) |DEBUG_UART_hal_obj   | UART HAL object used by Retarget-IO for the Debug UART port in main core secure app
 GPIO (PDL) | CYBSP_USER_LED1      | User LED1 from main core non-secure app
 GPIO (PDL) | CYBSP_USER_LED2      | User LED2 from PPCA Core 0 (for EVK kit)
 GPIO (PDL) | CYBSP_USER_LED3      | User LED3 from PPCA Core 1 (for EVK kit)
